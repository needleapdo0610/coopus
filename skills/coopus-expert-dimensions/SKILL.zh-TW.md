# coopus-expert-dimensions

## 一件事

把一個領域的專家會檢查的思考維度列出來，每個都要有深度，再套到使用者的設計上，找出沒考慮到的地方。

## 怎麼做

1. 寫出這次涉及的領域，可能不只一個，例如「架構 + 資安 + 成本」。
2. 每個領域列出專家會檢查的維度，通常五到八個。維度要具體，例如架構的「資料一致性」「可用性」「可觀測性」「遷移路徑」「成本」，不要寫「品質」「效能」這種太大的詞。
3. 每個維度回答四件事：

```
### <維度名稱>
在問什麼：<一句話，例如「兩處資料不一樣時，以誰為準」>
取捨：選 A 會犧牲什麼，選 B 會犧牲什麼
在這個情境什麼時候會出事：<套到使用者的設計，寫具體場景>
專家用什麼判斷：<數字或訊號，例如 p99 延遲、RPO/RTO、每月成本、錯誤率>
現況：已考慮 / 部分考慮 / 沒考慮
```

4. 最後一段列出「沒考慮」和「部分考慮」的維度，依風險排序，每個寫一個下一步。
5. 有外部事實或標準（例如某個服務的限制、某個法規），能查就查，附來源；查不到就標「未查證」。

## 不要做

- 不要寫「身為一位資深架構師，我認為...」。角色扮演只改語氣，不會多想到維度。
- 不要只列維度名稱。沒有取捨和失效情境的清單只有廣度。
- 不要直接給「最佳答案」。目的是讓使用者學會這個領域的判斷方式。
- 不要為了湊數加跟這個情境無關的維度。

## 驗證做對了

- 每個維度四個欄位都有填，「什麼時候會出事」引用了使用者設計裡的具體元素。
- 每個「專家用什麼判斷」都是可以量或可以觀察的東西。
- 至少一個維度的現況是「沒考慮」或「部分考慮」。如果全部都已考慮，重新檢查是不是維度列得太淺。

## 停下來問人

- 不知道使用者的規模、預算或限制，而這會讓取捨完全相反時。問一題，附上你預設的數字。
- 涉及法規、醫療、財務等需要專業執照判斷的領域時，標明這只是檢查清單，不是專業意見。
