# coopus-should-we-build

## 一件事

在談「怎麼做」之前，先判斷「該不該做」，最後給出做或不做的建議。

## 怎麼做

1. 用一到兩句話重述這個點子：解決誰的什麼問題。重述不出來就先問。
2. 列出目標使用者，至少兩種不同身份。每種寫：
   - 情境：他在什麼時候、做什麼事時碰到這個問題。
   - 現在怎麼解決：他目前用的方法或工具。
   - 為什麼換：新做法要好到什麼程度，他才願意換。
3. 市場比較：列出現有的替代品，包括「什麼都不做」和土法煉鋼。能查就自己查，附來源和查詢日期；查不到就寫「未查證」。
4. 反方：最強的三個反對理由。反方要真的能打，寫成懷疑者會說的話，不要稻草人。
5. 正方：最強的三個支持理由。
6. 關鍵未知：哪些事一旦知道答案，結論就會改變。每個未知寫出最便宜的驗證方式，例如訪談五個人、做一個登陸頁、查一份數據。
7. 給建議，格式固定：

```
建議：做 / 不做 / 先驗證再決定
信心：高 / 中 / 低，一句話說明原因
依賴的假設：
1. ...
翻盤條件：看到 <什麼證據>，建議會改成 <相反結論>
下一步：<最便宜的驗證，或交給 coopus-grill>
```

## 不要做

- 不要在這個階段講實作細節、技術選型或時程。
- 不要因為使用者看起來很想做就給「做」。先寫反方（第 4 步），可以降低附和。
- 不要用沒有來源的市場數字。
- 不要只給「看情況」。資訊不足時，建議就是「先驗證再決定」，並寫出要驗證什麼。

## 驗證做對了

- 至少兩種使用者身份，每種都有情境、現有做法、換的理由。
- 正反方各三點，而且反方至少有一點是使用者沒提過的。
- 建議區塊五個欄位都有填，翻盤條件寫的是看得到的證據，不是「如果情況改變」。
- 所有外部事實都有來源，或標成「未查證」。

## 停下來問人

- 點子的目標對象或要解決的問題完全不清楚時，先問一題，附上你猜的答案。
- 建議是「不做」或「先驗證」，但使用者已經投入很多時，把建議講清楚，由人決定，不要自己往下做。
- 判斷需要公司內部資料或私人資料時。
